## Objective and current state

Evaluate dw2lam/openlauncher for the owner's car head unit and, after compatibility checks, trial the standard APK while preserving a route back to the existing launcher.

Device model K4811 and Android 13 are owner-reported. The actual SDK, firmware, ABI, RAM, screen dimensions, existing launcher, and vendor radio packages have not been read from the device. Do not assume the advertised Android version is the real API level.

The owner successfully unlocked Android Developer settings and enabled USB debugging. No authenticated ADB connection has been established. No APK has been installed, no permissions have been granted through ADB, and no device settings, firmware, or default launcher have been changed by this work.

## Resume checklist

1. Ask whether an actual USB data connection to a vendor-supported Device/OTG port exists. Do not assume a head unit USB host port supports debugging. Avoid an unsupported USB-A-to-A connection.
2. Recheck the head unit's current IP; hotspot addresses can change. USB debugging alone does not establish that TCP ADB is enabled. If the ROM exposes Network ADB/TCP debugging, inspect its endpoint; do not keep assuming port 5555.
3. If a USB device appears as unauthorized, have the owner accept the device's RSA dialog. Do not bypass authorization. If USB works and network ADB is desired, use the supported ADB TCP workflow.
4. Once connected, explicitly target the device serial. Read only the model/manufacturer, SDK/release, ABI, RAM, screen size/density and current Home resolver/package state first. Avoid collecting personal files or broad device logs.
5. Check for an existing `com.openlauncher.app` installation and its signer/version before installing or updating. Record the existing Home component and an actionable rollback route before changing defaults.
6. Select a standard APK based on the actual device and review findings. v0.0.4 is the GitHub Latest release; v0.0.5 is an explicitly untested pre-release with fixes and a radio rewrite. Neither is validated on this car. Avoid the old platform-test-signed test-pip build.
7. Launch the app explicitly as a trial before changing the default Home app. Test denied permissions, offline use, media/radio, existing navigation/CarPlay receiver, Home behavior and sleep/wake. Owner-operated checks of reverse camera and steering-wheel controls should occur while safely parked.
